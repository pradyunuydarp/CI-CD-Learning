Project Overview

SciCalc Next is a scientific calculator web application engineered with Next.js 15.5.4, React 19, and TypeScript. The solution exposes a unified calculation API (`src/app/api/calc/route.ts`) that delegates to a typed mathematics library (`src/lib/math.ts`) covering square root, factorial, natural logarithm, and power operations with rigorous input validation. The client UI (`src/components/Calculator.tsx`) offers a responsive, keyboard-friendly workspace to interact with these capabilities.

The project emphasises maintainability and auditability. All core logic is unit-tested with Vitest (`src/lib/math.test.ts`), linted via ESLint 9, and formatted with Prettier 3. Developer ergonomics are supported through npm scripts and TypeScript configuration aligned with Next.js App Router best practices.

Architectural Blueprint

Frontend Delivery

  • Next.js App Router structure (`src/app/`) with server components for layout and a client-side `Calculator` widget for interactive input.
  • Global styling defined in `src/app/globals.css` to deliver a high-contrast, accessible experience across desktop and print views.
  • Typed props and state management ensure predictable render flows and reduce runtime regressions.

Service & Domain Logic

  • Mathematics module implements sqrtX, factX, lnX, and power with defensive guards for invalid input and overflow scenarios.
  • API route normalises requests into a discriminated union, reusing the domain module to keep business rules in one place.
  • Explicit error handling returns actionable HTTP 400 responses for unsupported or malformed operations.

Quality Assurance

  • Vitest suite validates happy paths and edge cases for each mathematical operation and the combined evaluate dispatcher.
  • ESLint (Next.js preset) enforces code quality gates, while Prettier standardises formatting across TypeScript, TSX, JSON, and styling assets.
  • Automated scripts (`npm run lint`, `npm run test`, `npm run build`) provide deterministic checks for the CI pipeline.

DevOps Toolchain

  • Docker multi-stage build (`Dockerfile`) packages the production-ready Next.js server with minimal footprint.
  • Jenkins pipeline (`Jenkinsfile`) orchestrates install, test, build, and push phases with Docker Hub credential management.
  • Ansible playbook (`ansible/playbooks/deploy.yml`) ensures repeatable container deployment using the `community.docker` collection.

Automated Quality Gates

  • Unit validation: Six targeted Vitest specs cover deterministic outputs, error pathways (negative roots, non-integer factorial inputs, overflow), and the `evaluate` dispatcher contracts.
  • Static analysis: ESLint scans TS/TSX modules with Next.js rules, catching unused imports, unsafe React patterns, and TypeScript inconsistencies before build.
  • Formatting: Prettier script maintains consistent whitespace and quotation style across the repository, avoiding diff churn between contributors.
  • Deterministic installs: `npm ci` combined with `package-lock.json` stabilises dependency resolution for both local development and pipeline runs.

Containerisation & Deployment

Docker Image Strategy

  • Builder stage installs dependencies and compiles the Next.js application.
  • Runtime stage copies the `.next` output and production dependencies into a slim Node.js base image.
  • Entrypoint executes `next start`, exposing the service on port 3000 for downstream reverse proxies or load balancers.

Ansible Playbook Highlights

  • Inventory targets are defined in `ansible/inventory/hosts.ini`; default configuration operates against localhost with a local connection.
  • `ansible/playbooks/deploy.yml` pulls the tagged Docker image (default: `dockerhub-user/sci-calc-next:latest`) and guarantees the container runs with `restart_policy: always`.
  • Customise the deployment by exporting DOCKER_IMAGE or overriding extra variables (`container_name`, `host_port`).

Operational Runbook:

  1. Install Ansible dependencies: ansible-galaxy collection install -r ansible/requirements.yml.
  2. Set the desired Docker image reference (optional): export DOCKER_IMAGE=<registry-user>/sci-calc-next:latest.
  3. Execute the deployment: cd ansible && ansible-playbook playbooks/deploy.yml.
