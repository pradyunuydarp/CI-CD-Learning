\section{Introduction}
SciCalc Next is the scientific calculator that supports the SPE Mini Project. The goal was to deliver four advanced operations, wrap the logic inside a Next.js interface, and prove a complete CI/CD story from local code all the way to an Ansible driven deployment. This document keeps the wording simple and tracks each artefact we produced while following the brief in \textit{SPE -- Mini Project Instructions.pdf}.

\section{Setup and Architecture}
\begin{itemize}[leftmargin=*]
  \item Next.js 15 with the App Router powers the UI. Pages live under \texttt{src/app}; reusable UI pieces sit in \texttt{src/components}.
  \item All maths lives in \texttt{src/lib/math.ts}. The module exports \texttt{sqrtX}, \texttt{factX}, \texttt{lnX}, and \texttt{power}, matching the operations listed in the assignment.
  \item The calculation API is exposed at \texttt{src/app/api/calc/route.ts}. The client form sends one payload to this route, keeping validation in one place.
  \item Global layout is defined in \texttt{src/app/layout.tsx}. Styling sticks to flex layouts so the screen reads well on laptops and tablets.
\end{itemize}

\section{Requirement Coverage}
Each item from the mini project checklist is satisfied as follows:
\begin{enumerate}[leftmargin=*]
  \item \textbf{Scientific operations} --- factorial, square root, natural log, and exponentiation are exposed in the UI and API. Invalid inputs (negative factorials, zero logarithms, empty bases) return clear error messages.
  \item \textbf{Automated tests} --- Vitest specs under \texttt{src/lib/math.test.ts} cover happy paths and edge cases. They run through \texttt{npm run test} and are wired into Jenkins.
  \item \textbf{Quality gates} --- ESLint runs through \texttt{npm run lint}. Prettier is ready through \texttt{npm run format}. These scripts close the testing and linting requirement.
  \item \textbf{Containerisation} --- The multi-stage Dockerfile builds the Next.js output and runs it inside a slim Node 20 Alpine image. Local developers can run \texttt{docker build -t sci-calc-next:dev .}.
  \item \textbf{Continuous integration} --- Jenkins executes install, lint, test, build, and Docker push stages. Docker Hub and Vault credentials are stored as Jenkins secrets, satisfying the secure credentials requirement.
  \item \textbf{Continuous delivery} --- Ansible playbooks live under \texttt{ansible/}. The deploy playbook pulls the pushed image and keeps the container running on port 3000.
  \item \textbf{Documentation} --- This report, the change log, README, and ANSIBLE guide are updated after each milestone, meeting the reporting expectation.
\end{enumerate}

\section{Automated Testing}
\begin{itemize}[leftmargin=*]
  \item \textbf{Unit tests} --- \texttt{npm run test} executes Vitest in CI. Any failure blocks the Docker build stage.
  \item \textbf{Static analysis} --- \texttt{npm run lint} enforces the Next.js ESLint preset. The job prints the deprecation warning about `next lint` so the team can plan a migration.
  \item \textbf{Repeatable installs} --- \texttt{npm ci} runs in every pipeline, guaranteeing the lockfile controls dependency state.
\end{itemize}

\section{CI/CD Pipeline}
\begin{itemize}[leftmargin=*]
  \item Jenkins pulls the repository, runs the scripts above, and builds the production bundle with `NODE\_ENV=production` applied only during the build command.
  \item The Docker stage logs which user is in use, logs into Docker Hub, builds \texttt{<user>/sci-calc-next:latest}, and pushes it.
  \item The Ansible stage now runs on every build. It installs collections inside a virtual environment, exports the absolute interpreter path so Docker modules resolve correctly, picks an open host port (preferring 3000 but falling back when busy), decrypts Vault secrets with the injected password, and applies \texttt{playbooks/deploy.yml}.
\end{itemize}

\section{Docker and Ansible Deployment}
\begin{itemize}[leftmargin=*]
  \item \textbf{Inventory} --- \texttt{ansible/inventory/hosts.ini} targets localhost but can be extended with remote hosts.
  \item \textbf{Group vars} --- \texttt{ansible/inventory/group\_vars/all.yml} holds the Docker image tag, port defaults, and wires `ANSIBLE\_PYTHON\_INTERPRETER` to the Jenkins virtual environment value the pipeline exports after building its venv.
  \item \textbf{Cleanup + Vault} --- \texttt{ansible/vault/secrets.yml} (encrypted) stores Docker Hub credentials while the deploy playbook now stops and removes any stale container before recreating it with the resolved host port, ensuring we never conflict with an older run.
  \item \textbf{Playbooks} --- \texttt{playbooks/ping.yml} checks connectivity. \texttt{playbooks/deploy.yml} logs in, pulls, and manages the container with the \texttt{always} restart policy without requiring sudo access.
\end{itemize}

\section{Results and Evidence}
\begin{itemize}[leftmargin=*]
  \item Latest Docker push digest: pending next Jenkins run after the interpreter fix.
  \item Deployment recap: Ansible now frees any stale container, selects an available host port automatically, and is expected to recreate the service on the next Jenkins rerun (the interpreter issue is already fixed).
  \item Commands to reproduce locally: \texttt{npm run lint}, \texttt{npm run test}, \texttt{npm run build}, \texttt{ansible-playbook playbooks/deploy.yml}.
\end{itemize}

\section{Learnings and Improvements}
\begin{itemize}[leftmargin=*]
  \item Input validation reminded us to clamp values early. The UI now blocks negative factorials and exposes friendly errors for log requests.
  \item Jenkins initially missed devDependencies when `NODE\_ENV` was exported globally, so the pipeline now scopes that setting to the build command only.
  \item Future work: migrate from `next lint` to the standalone ESLint CLI, cache the Ansible virtual environment in Jenkins, and add Playwright smoke tests for the UI.
\end{itemize}
